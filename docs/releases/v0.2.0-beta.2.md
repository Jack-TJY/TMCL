TMCL 的第二个 Beta 公测版。修复 beta.1 测试中发现的问题，安装 Fabric 时默认附带 Fabric API，缺失的前置可以从另一平台补全，皮肤库位置可自定义。这是测试版本，可能存在问题，欢迎在 [Issues](https://github.com/Jack-TJY/TMCL/issues) 反馈（附上“设置 → 存储 → 导出诊断信息”生成的 zip 更好）。

> TMCL 是非官方启动器，与 Mojang Studios 和 Microsoft 没有关联。

## 新增

- 安装 Fabric 时默认同时安装 Fabric API：下载页新建实例、资源页一键新建实例、更换加载器时都有默认勾选的“同时安装 Fabric API”，实例中已有 Fabric API 时跳过；安装整合包时不额外安装。Fabric API 安装失败时加载器照常装好，并提示到资源页重新安装，提示中可直接打开该实例的资源页（#202）。
- 必需前置在来源平台上没有适用的版本时，自动到另一平台（Modrinth ↔ CurseForge）查找同一个 mod 并加入安装计划，安装对话框中标出“来自 CurseForge / Modrinth”；不兼容的资源仍会提示，由你手动处理（#200）。
- 皮肤库位置可自定义：放到网盘同步文件夹或指向另一个 TMCL 的皮肤库，即可在多台电脑、多个安装目录间共用；更改时可以把现有皮肤复制过去。皮肤库改为每张皮肤一个描述文件，同步时不会互相覆盖，旧皮肤库首次打开时自动迁移（#199）。
- 联机时 EasyTier 的输出写入 `tmcl-data/p2p/easytier.log`（保留当前和上一份，每份不超过 2 MB），并随诊断信息包导出；导出时去掉网络密钥、个人信息与 IP 地址（#201）。
- Windows 安装包接入 [SignPath](https://signpath.org) 免费代码签名流程，申请通过后生效；新增 [代码签名政策与隐私政策](https://github.com/Jack-TJY/TMCL/blob/main/docs/CODE_SIGNING.md)，README 补充 SmartScreen 拦截时的处理方法（#198）。

## 修复

- Fabric 实例安装 Jade 等 mod 后因缺少 Fabric API 启动崩溃（B2，#202）。
- 资源页一键新建实例时，默认的游戏版本不看所选加载器，可能选到该资源没有文件的版本；现在只列出资源在所选加载器上支持的游戏版本，换加载器时重新筛选（C2b，#202）。
- 设置 → Java 显示“尚未发现 Java”：现在列出 TMCL 自动下载的 Java 与系统中的 Java（B5，#201）。
- 导出诊断信息时保存对话框默认在根目录：现在默认在“下载”文件夹，文件名带日期时间（B6，#201）。
- 1280 宽度窗口下实例页搜索框被挤窄、按钮挤到第二行，关于页 EasyTier 网址超出卡片（B8，#201）。
- 资源页按 CurseForge 筛选时装好的资源不显示“已安装”，已安装的行仍显示“安装”按钮（B3，#待补）。
- 离开资源页再回来，选中的实例与平台筛选被重置（B4，#待补）。
- 选定整合包后版本列表要十几秒才出来，现在快很多（B7，#待补）。

## 已知问题

- Forge 1.7.10 无模组时进入主菜单可能崩溃，是 Forge 自身的问题（Alpha D1）。
- 默认窗口大小下首页“快捷操作”组件需要内部滚动（Alpha D3）。
- Linux 上 WebKit 会在 `tmcl-data` 之外写入少量数据，卸载后残留（Alpha D11）。
- 直连联机首次连接可能需要等待十几秒，个别网络下第一次会失败、重试后成功；一直连不上时请改用樱花穿透。
- 实例的资源管理页（已安装、启用 / 禁用、检查更新）尚未在真机上完整测试，欢迎反馈。
- 皮肤库迁移为新格式后，0.2.0-beta.1 及更早的 TMCL 读取同一个皮肤库会显示为空（文件不受影响）；共用皮肤库的各个 TMCL 请都升级到本版本。
- 皮肤库放在同步文件夹时，别处同步来的改动要重新进入皮肤页才显示。
- Windows 安装包暂未签名（代码签名申请中），SmartScreen 拦截时点“更多信息”→“仍要运行”。
- macOS 版本尚未测试。
- 暂不支持自动更新，新版本需要手动下载。

## English

The second beta of TMCL. It fixes issues found while testing beta.1, installs Fabric API together with Fabric by default, fills in missing required dependencies from the other platform, and lets you choose where the skin library lives. This is a test build and may have issues; please report them in [Issues](https://github.com/Jack-TJY/TMCL/issues), ideally with the zip from Settings → Storage → Export diagnostics.

> TMCL is an unofficial launcher and is not affiliated with Mojang Studios or Microsoft.

**New:** Fabric API is installed with Fabric by default (new instance, one-click instance and loader change; not for modpacks), and if it fails the loader is still installed and you are pointed to the Resources page to retry; required dependencies missing on one platform are taken from the other (Modrinth ↔ CurseForge) and labelled in the install dialog; the skin library can live in any folder, such as a cloud-synced one shared between PCs or installs, with one descriptor file per skin and automatic migration; the EasyTier log is saved to `p2p/easytier.log` and included in diagnostics with personal data and IP addresses removed.

**Fixed:** mods like Jade crashing on Fabric without Fabric API; one-click new instance offering game versions the resource has no files for; Settings → Java showing no Java; the diagnostics save dialog opening at `/` (now Downloads, with a timestamped name); layout issues at 1280 px; CurseForge resources not shown as installed and installed rows still offering Install; the Resources page forgetting the selected instance and platform filter; the slow modpack version list.

**Known issues:** after migration, beta.1 and older can't read the new skin library format and show it as empty (files are untouched), so upgrade every TMCL that shares it; direct P2P can take a dozen seconds to connect and may need a retry; Forge 1.7.10 without mods may crash at the menu (a Forge bug); the Windows installer is not code-signed yet (click "More info" → "Run anyway" in SmartScreen); the macOS build is untested and unsigned; no auto-update yet.

Checksums are in `SHA256SUMS.txt`.
