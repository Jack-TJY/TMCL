# Alpha 测试矩阵（M1-17）

本文件记录 `v0.1.0-alpha.1` 发布前的测试结果。每一轮测试追加一节，不改旧记录；缺陷按下方等级登记，P0 必须在 G2 前修复。

| 等级 | 含义 |
| --- | --- |
| P0 | 主流程不可用（无法安装、无法启动、数据丢失、泄露令牌），必须修复后才能发布 |
| P1 | 功能可用但有明显问题，或只影响个别版本 / 加载器；可登记为已知问题随 Alpha 发布 |
| P2 | 体验问题 |

结果记号：✅ 通过 · ❌ 失败 · ⚠️ 通过但有已知问题 · ⏳ 待测 · — 不适用

### 缺陷

| 编号 | 等级 | 描述 | 处理 |
| --- | --- | --- | --- |
| D1 | P1 | Forge 1.7.10（10.13.4.1614，无模组）进入主菜单开始放音乐时崩溃：`UnsatisfiedLinkError: AL10.nalGetSourcei`。原因是 Forge 启动时连续两次重载资源，第二次在第一次后约 0.33 秒，而本机首次声音初始化约需 0.65 秒；`SoundManager` 在首次加载完成前不会释放旧的 OpenAL 上下文，于是第二次创建报 `Only one OpenAL context may be instantiated`，30 秒后转入静音模式，随后音乐播放调用到已失效的 OpenAL 句柄而崩溃。原版 1.7.10 只重载一次，不受影响；关闭 Forge 启动画面（`splash.properties` 的 `enabled=false`）后仍复现。 | Forge 自身的竞态，启动器参数无误。登记为已知问题；装有模组时两次重载间隔变长，通常不触发。 |
| D2 | P1 | 游戏日志窗口显示原始 log4j XML（`<log4j:Event …><![CDATA[…]]>`），而不是可读的日志行；行数也按 XML 行计数。原因是版本 JSON 的 `logging.client` 配置使用 XMLLayout 输出到标准输出，而启动器没有解析。 | 已修复：#106 在 `core/launch` 读取标准输出时把 log4j XML 事件转换为 `[时间] [线程/级别]: 消息` 文本行（异常堆栈附在后面），崩溃识别基于转换后的行；#107 补充数字字符引用（见第 2 轮 D5）。 |
| D3 | P2 | 默认窗口大小（1100×700）下首页“快捷操作”组件需要内部滚动，第三个按钮被截断。 | 可调整默认布局中该组件的高度。 |

本轮未发现 P0。
